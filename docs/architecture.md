# Architecture

## Processes and storage

The Hub is one Go process with embedded Web assets, SQLite or PostgreSQL metadata, and content-addressed local ZIP packages. CLI and desktop embed the same Go client core. Desktop uses Wails with React/TypeScript; a separate Go module keeps native dependencies out of Hub/CLI builds.

SQLite uses WAL on local disk. PostgreSQL uses `database/sql` with a pgx adapter, dialect translation and transactional migrations. A session advisory lease establishes single-process ownership before initialization or migration. Queries remain bound to that physical connection; ownership loss rejects requests and shuts down serving. Stop the old process before replacement. Multiple serving replicas and network-shared package storage are not supported.

## Protocol

- `proto/api/<domain>/v1` owns unary Connect services; `proto/api/common/v1` owns paging/error envelopes and `proto/common/<domain>/v1` owns shared enums.
- Generated Go and TypeScript clients are the transport boundary. Domain commands, entities and persistence records use their own types. There is no second REST business API.
- Public errors use Connect codes and typed safe details. Secrets and package contents never enter logs/errors. Binary Protobuf and ProtoJSON have equivalent authorization semantics.
- Authenticated identity comes from verified credentials. Mutation keys support idempotent retries; they do not bypass current authorization.
- Opaque cursors bind identity, filters and ordering. Unknown enum values fail closed. Bounded package bodies travel through typed RPCs.
- Registry discovery advertises a protocol major and named capabilities. A client reports unsupported operations per connection instead of silently dropping requested filters or fields.
- `make proto` generates Go/TypeScript; `make proto-check` checks generated drift. Published field identities must not be reused. Native bindings are regenerated by `desktop/build.mjs`.

## Identity and authorization

The Hub has local accounts and one optional OIDC provider. External identities bind verified issuer/subject, not email. Pending admission creates no usable session. Administrators approve ordinary membership separately from namespace/platform permissions.

Browser sessions use HttpOnly, SameSite cookies with Origin and custom-header checks. CLI/App hold independent Hub-issued tokens through the OS credential store. OIDC state, nonce and PKCE attempts are single-use, bounded and expire after five minutes; restart invalidates incomplete login. IdP tokens are not retained. Callback/login pages are browser transport endpoints, not a second business API.

Every content operation rechecks release state and audience. Namespace roles, group audiences and platform duties have distinct responsibilities. Profile projections redact login identity except for authorized administrative/self access. See [identity and access](identity-and-access.md).

## Catalog and governance

Immutable releases contain package digests, audience and presentation metadata. Queries select the latest readable published release before filtering by query/category/tags/curation. Recent ordering uses publication sequence and deterministic cursor paging. Curation is a Hub-admin mutation keyed by namespace/name; it does not bypass authorization.

Review tasks are a live query over actionable pending submissions. The same independent-review rule excludes self-submissions. Count, oldest timestamp and page are read consistently. A decision, its audit record and the submitter's notification commit together. Notification replay/read state remains owner- and permission-scoped.

Package inspection is bounded and offline. Reports bind the package digest and scanner version. Blocking findings cannot be overridden; warnings or incomplete inspection require independent review and a note. See [governance](governance.md).

## Community

Profiles, team profiles, comments, reactions and avatars are stored with Hub metadata and included in paired backups. `api.community.v1.CommunityService` owns the transport contract; domain projections live in `internal/community`.

Comments are capped at 4,000 Unicode characters and 20 new comments per user per minute. Replies target an undeleted root in the same release. Removal leaves a tombstone, including on idempotent replay. Profile revisions prevent lost concurrent edits. All reads and mutations recheck release visibility and current access.

Avatar input is limited to PNG/JPEG, 512 KiB and 2048×2048. The server crops/re-encodes a 128×128 PNG, removes metadata and never fetches arbitrary URLs. Initials are the fallback.

## Shared client core

`internal/client` owns sources, credentials, generated remote clients, packages, target adapters, plans, local inventory and project manifests. CLI/App only adapt interaction; the core does not depend on UI frameworks.

Cross-process file locks coordinate local changes. SQLite transactions coordinate records, while installation journals bridge the filesystem/database crash boundary. Apply rechecks a single-use plan, authorization, exact digest and unmodified target. Actual target aliases cannot produce multiple physical owners. Unmanaged/modified files require explicit user resolution.

Installations retain canonical Hub ID/URL, exact version/digest and the connection's opaque reference. Connection recovery verifies that the selected identity still addresses the same Hub and updates records under the target lock; it does not rewrite skill files. Local inventory can render stored presentation without contacting a Hub.

`skillhub.json` holds exact desired versions/tools; `skillhub.lock.json` holds manifest digest, source identity, canonical URL, version, archive digest and relative target. Project metadata has its own cross-process lock. Restoration uses configured sources, rechecks download access, preflights targets and reports per-target results.

The ZIP cache is keyed by Hub identity/address and exact coordinate, bounded to 128 entries/256 MiB with LRU eviction. Atomic writes and a cache lock coordinate clients. Reuse still checks online download authorization and the blob digest. Cache failure falls back to network download, never offline authorization.

## Shared interface

React views build for either the browser or Wails. A typed adapter selects generated Connect clients or native Go bindings. Source context stays explicit; local inventory has no global Hub identity. Language/theme preferences are per device; authored content is not translated. macOS/Windows titlebars follow the selected theme through native adapters.

Skill files render as bounded text/Markdown without script execution. Browser installation offers instructions and downloads; native clients perform planned filesystem writes. App release discovery contacts only the software distribution service, never a Hub-selected executable source.

The `/docs/` route serves a static Next.js/Fumadocs export generated from the canonical repository guides, with browser-local search. Its per-page CSP permits only the generated inline script hashes. Documentation is public software content, separate from Hub authentication and private data; Node.js is a build dependency only.

## Maintenance and verification

SQLite backup creates a consistent snapshot and copies exactly its referenced package digests. PostgreSQL maintenance pairs a native database dump with packages while holding exclusive ownership. Restore accepts fresh destinations, preserves registry identity, invalidates sessions/devices and records an audit event. Markers prevent incomplete recovery from serving. Upgrade/rollback is an operator workflow, not an in-place schema downgrade.

Schema migrations, recovery guards and permission checks are maintained product behavior. Test reports, machine-specific deployment material and development decisions belong in CI artifacts or ignored local storage. See [database maintenance](database.md), [operations](operations.md) and [testing](testing.md).
