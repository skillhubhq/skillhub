# 安全策略

## 报告漏洞 [#reporting-a-vulnerability]

优先使用 [GitHub 私密漏洞报告](https://github.com/skillhubhq/skillhub/security/advisories/new)。若不可用，通过已有私密渠道联系维护者安排安全传递。不要把利用细节、秘密或私有技能正文放到公开 Issue；预览期间不承诺响应 SLA。

提供受影响版本、部署模式、合成数据最小复现和影响。不得提交真实令牌、密码、cookie 或完整私有包。

## 支持版本 [#supported-versions]

项目处于预览，安全修复针对当前维护代码及下一版本，旧预览不承诺独立回补。预览发布不代表生产就绪，部署前查看发布说明和候选验收证据。

## 安全边界 [#security-boundaries]

Hub 校验发布和下载权限。CLI/App 保留本地修改、验证摘要，不执行包脚本；安装不代表指令可信，交给 Agent 前仍需审阅。已下载副本不能因撤下远程删除。

客户端以本地用户权限运行，状态/项目目录由用户控制，应限制为该用户访问。归档和 manifest 不可信，安装前检查路径、符号链接、完整性；项目工具目录不能逃出项目。目录句柄约束并发路径替换，但用户仍需独占安装父目录和私有状态；恢复保留被修改的原始备份。构建/打包/测试工具允许维护者明确选本地程序和输出路径，不是对外 Hub API。

外部评测只校验格式、摘要和权限，不能证明观察真实。发布前清除私有提示词和凭据，证据受众跟随技能版本，静态规则不可能识别所有秘密。

使用 HTTPS、内部内容私有模式、受控持久存储和独立验证备份。企业认证与 Hub 授权分开；Entra 禁用不即时撤销 Hub 会话，应同时禁用 Hub 用户。

校验和检测损坏，单独不能认证发行者；若有 GitHub attestation，可检查来源证明。预览 App 未提供正式签名/公证，遵守设备正常安全策略。
