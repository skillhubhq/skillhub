# App 更新

App 仅在用户请求时查询 GitHub Releases，打开确切版本页面手动下载，不后台下载安装、不自替换。macOS 为 ad-hoc 签名，不含 Developer ID 或 Apple 公证。

## 检查与安装 [#check-and-install]

设置 → 更新显示版本/构建，选择稳定或预览渠道后检查，按语义版本排序而非上传时间。缺少平台包、仓库不可用、限流、网络失败均明确报告，不伪称已最新。达到 100 条查询上限则标记无法确认完整性。

发布说明按无执行能力的文本显示。macOS 先退出 App，打开 DMG，通过 Applications 快捷方式替换，弹出磁盘后重开。核对摘要并遵循系统正常安全策略。DMG 是包装格式，不证明发行者身份。

配置、凭据引用、安装清单、草稿和偏好位于 bundle 外。替换时保留它们；格式变化前先备份。降级需要兼容程序/状态快照，替换 App 不应顺便回退技能目录。

## 状态保留 [#state-preservation]

| 状态 | 位置 |
| --- | --- |
| 连接、凭据引用、清单、项目入口 | `SKILLHUB_HOME` 或 OS 配置目录下 `skillhub` |
| 保存的技能草稿 | 客户端目录的 `drafts/`，发布页可重新打开 |
| 凭据 | OS 凭据存储，不在 App 或客户端目录备份里 |
| 语言、主题、当前社区 | WebView profile，需保持 OS 用户和应用身份 |
| 已安装技能、项目清单/锁 | 原全局或项目目录，不因 App 替换而修改 |

先保存编辑文件，退出 App/CLI，再备份整个关闭状态的客户端目录、所需项目/全局文件和含 WebView profile 的设备备份，保留旧程序。不要只复制活动 SQLite 主文件。目录备份不能跨设备携带凭据，换设备/用户可能需逐源重登。

重开后验证各 Hub 身份、语言主题、草稿、清单、锁和安装文件（含本地修改）。未保存编辑文字和未提交表单不是持久化草稿，Web 发布草稿仅当前页面有效。

回退前退出所有客户端；旧程序支持当前格式才可直接运行，未来 schema 必须不改数据并拒绝。否则恢复匹配快照并核对快照后安装/编辑，不可假定任意降级都支持。Hub 数据库恢复是独立流程。

## 更新边界 [#update-boundaries]

| 对象 | 负责者 | 影响 |
| --- | --- | --- |
| Hub/Web | 部署运维 | 服务程序、迁移、包存储 |
| App | 用户或 IT | 应用 bundle、共享客户端状态 |
| CLI | 用户或包管理器 | CLI 程序、共享状态 |
| 技能 | 用户确认安装计划 | 来源 Hub 的指定受管文件 |

多个 Hub 仍只有一个 App 软件更新渠道。Hub 不能指定可执行下载 URL、签名密钥或更新器；远端不支持的能力只影响该连接。App 更新不更新 Hub、技能或项目锁。

## 网络与信任 [#network-and-trust]

更新请求有数量/超时限制，不包含 Hub 凭据、URL、搜索、项目清单或持久设备标识。不嵌入 GitHub 私有令牌，私有分发通过用户浏览器正常权限访问。

校验和只能检测损坏，无法独立认证被攻陷的下载源；检查来源及可用证明。不支持自动安装、签名服务集成或其他更新源。参见[分发](distribution.md)与[测试](testing.md)。
